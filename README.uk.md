# RentalCar

Вебзастосунок для оренди автомобілів, зроблений за макетом у Figma: перегляд
каталогу, фільтрація на боці бекенду, довантаження карток сторінка за сторінкою,
відкриття деталей авто в новій вкладці та надсилання заявки на оренду.

**Посилання:** https://rental-car-hontonoran.vercel.app

## Можливості

- **Домашня сторінка (`/`)** — hero-секція з кнопкою `View Catalog`.
- **Каталог (`/catalog`)** — сітка автомобілів із фільтрацією на бекенді за
  брендом, ціною за годину та діапазоном пробігу. Фільтри зберігаються в URL
  (`/catalog?brand=Buick&price=40&minMileage=1000&maxMileage=6000`), тож
  відфільтрований каталог можна переслати, додати в закладки й перезавантажити.
- **Пагінація Load More** — `useInfiniteQuery` з TanStack Query дозавантажує
  наступну сторінку автомобілів, зберігаючи активні фільтри.
- **Сторінка авто (`/catalog/[carId]`)** — повні характеристики, умови оренди,
  список опцій і фотографія. Відкривається з картки каталогу в новій вкладці.
- **Форма оренди** — валідація через Formik + Yup, після успішної відправки
  показується сповіщення.
- **Обране (`/favorites`)** — збереження авто через сердечко на картці.
  Ідентифікатори зберігаються в `localStorage`, а лічильник видно в шапці.
- **Стани завантаження та помилок** — власний лоадер поверх скелетону,
  ілюстрований стан «No cars found» і error boundary з кнопкою повтору.

## Архітектура

Серверні компоненти відповідають за завантаження даних, клієнтські — за
взаємодію з користувачем.

- `app/catalog/page.tsx` (Server) читає фільтри із `searchParams`, заздалегідь
  завантажує автомобілі та опції фільтрів у `QueryClient` і передає
  дегідратований кеш через `HydrationBoundary`.
- `app/catalog/CatalogClient.tsx` (Client) підписується на ті самі ключі
  запитів, тому дані є вже на першому рендері, і далі обробляє Load More та
  зміну фільтрів.
- `app/catalog/[carId]/page.tsx` (Server) завантажує одне авто й рендерить
  деталі; клієнтським компонентом є лише форма оренди.
- `lib/queries.ts` містить спільні описи запитів, тож сервер і клієнт не можуть
  розійтися.

```
app/            маршрути, layout-и, метадані
components/     UI-компоненти, кожен зі своїм CSS-модулем
hooks/          useFavorites (localStorage + useSyncExternalStore)
lib/            API-клієнт, опції запитів, робота з фільтрами, форматування
providers/      провайдер TanStack Query
types/          спільні типи API
```

### Зображення

`app/icon.svg`, `app/apple-icon.png` і `app/opengraph-image.jpg` — це файлові
конвенції Next.js: самі їхні назви генерують фавікон, іконку для iOS і картку
для соцмереж, тому вони мають лишатися в `app/` саме з такими іменами.
Перейменування будь-якого з них тихо прибирає відповідний тег із `<head>`.

Зображення, які імпортують компоненти — `hero-car.jpg`, `no-cars-found.png` —
лежать у `public/` і віддаються через `next/image` як оптимізований WebP.

## Запуск

Потрібні Node.js 20+ та npm.

```bash
git clone https://github.com/hontonoran/rental-car.git
cd rental-car
npm install
npm run dev
```

Застосунок буде доступний на http://localhost:3000.

### Команди

| Команда | Опис |
| --- | --- |
| `npm run dev` | Запустити сервер розробки |
| `npm run build` | Зібрати продакшн-версію |
| `npm start` | Запустити продакшн-збірку |
| `npm run lint` | Перевірити код ESLint |
| `npm run typecheck` | Перевірити типи TypeScript |

### Змінні оточення

Необовʼязкові. `NEXT_PUBLIC_SITE_URL` можна вказати як адресу задеплоєного
застосунку, щоб посилання в метаданих були абсолютними. За замовчуванням
використовується адреса на Vercel.
